[^gcc]: **Now verified.** `strings $(which simpleFoam) | grep "^GCC:"` reports
`GCC: (GNU) 8.5.0 20210514 (Red Hat 8.5.0-26)` and `(Red Hat 8.5.0-28)`, read
from the shipped binary itself rather than inferred from the runtime
environment, so the site `OpenFOAM/2512` module was built with GCC 8.5.0. The
node compiler matches: `gcc (GCC) 8.5.0 20210514 (Red Hat 8.5.0-28)`. This
closes the adapter's "exact GCC sub-version TBD".

**Consequence for optimisation.** GCC 8.5.0 dates from 2021 and predates
Sapphire Rapids support in GCC, which arrived in GCC 11 (`-march=sapphirerapids`).
The site module therefore cannot have been tuned for the scored hardware, and is
compiled for a generic x86-64 target. That is a genuine, evidenced headroom
argument for a self-built stack - no artificial baseline is needed to make the
case.
